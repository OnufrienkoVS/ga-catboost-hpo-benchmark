# Оптимизация гиперпараметров CatBoost с помощью генетического алгоритма

Исследовательский проект по сравнению генетического алгоритма, TPE и случайного поиска при оптимизации гиперпараметров модели CatBoost в задачах бинарной классификации.

## 1. Цель проекта

Цель проекта - исследовать эффективность генетического алгоритма при оптимизации гиперпараметров CatBoost в условиях ограниченного вычислительного бюджета.

Сравниваются три подхода:

- **Genetic Algorithm (GA)** - генетический алгоритм, реализованный с использованием DEAP.
- **Tree-structured Parzen Estimator (TPE)** - байесовская оптимизация из библиотеки Optuna.
- **Random Search** - случайный поиск по заданному пространству гиперпараметров.

Основной вопрос исследования: способен ли генетический алгоритм находить более качественные конфигурации CatBoost, чем альтернативные методы, при одинаковом количестве вычислений целевой функции?

## 2. Гипотезы исследования

В рамках проекта планируется проверить следующие гипотезы:

1. **Качество оптимизации.** Генетический алгоритм достигает более высокого ROC-AUC, чем Random Search, при одинаковом вычислительном бюджете.
2. **Влияние бюджета.** Относительная эффективность генетического алгоритма зависит от доступного количества вычислений целевой функции.
3. **Сходимость и стабильность.** Генетический алгоритм демонстрирует отличающиеся характеристики скорости сходимости и вариативности результатов по сравнению с TPE и Random Search.

## 3. Экспериментальный дизайн

### Модель

В качестве алгоритма классификации используется `CatBoostClassifier`.

### Датасеты

Планируется использовать два датасета для бинарной классификации:

- **German Credit** (`credit-g`) - задача кредитного скоринга.
- **QSAR biodegradation** - задача классификации химических соединений по биоразлагаемости.

### Пространство гиперпараметров

На начальном этапе планируется оптимизировать следующие параметры CatBoost:

| Гиперпараметр         | Тип   | Диапазон |
|-----------------------|-------|----------|
| `depth`               | int   | 4-10     |
| `learning_rate`       | float | 0.01-0.3 |
| `l2_leaf_reg`         | float | 1-10     |
| `bagging_temperature` | float | 0-5      |
| `random_strength`     | float | 0-5      |
| `border_count`        | int   | 32-255   |

Окончательные настройки пространства поиска будут зафиксированы до проведения основного эксперимента.

### Метрика качества

Основная метрика - **ROC-AUC**.

Для оценки качества конфигураций будет использоваться стратифицированная кросс-валидация. Тестовая выборка будет отделена от процесса оптимизации и использована только для итоговой оценки выбранных конфигураций.

### Сравниваемые методы

Все оптимизаторы будут работать с одинаковым пространством гиперпараметров и сопоставимым вычислительным бюджетом.

Предварительный план эксперимента:

| Параметр                       | Значение                       |
|--------------------------------|-------------------------------:|
| Количество датасетов           | 2                              |
| Количество оптимизаторов       | 3                              |
| Повторения с разными seed      | 10                             |
| Основной бюджет                | 100 вычислений целевой функции |
| Контрольные точки бюджета      | 25, 50, 100                    |
| Предварительное число запусков | 60                             |

Дополнительно будут анализироваться:

- ROC-AUC на разных этапах оптимизации;
- время выполнения;
- скорость сходимости;
- вариативность результатов между запусками.

Параметры экспериментального протокола могут быть уточнены по итогам пилотного запуска. Все изменения должны быть зафиксированы до основного эксперимента.

## 4. Статистический анализ

Для сравнения оптимизаторов будут использоваться статистические методы, учитывающие парность экспериментальных результатов.

В зависимости от структуры итоговых данных планируется применить:

- критерий Фридмана и post-hoc анализ Nemenyi;
- либо парные критерии Уилкоксона с поправкой Холма на множественные сравнения.

Статистические тесты будут применяться к сопоставимым результатам запусков. Уровень статистической значимости - `p < 0.05`.

## 6. Установка и настройка окружения

### Требования

- Python 3.12.10
- [uv](https://docs.astral.sh/uv/)
- Git

Для управления версией Python используется `pyenv-win`, а для управления зависимостями и виртуальным окружением - `uv`.

### Клонирование репозитория

```bash
git clone https://github.com/OnufrienkoVS/ga-catboost-hpo-benchmark.git
cd ga-catboost-hpo-benchmark
```

### Выбор версии Python

В проекте используется Python 3.12.10. Версия закреплена в файле `.python-version`.

Если используется `pyenv-win`, можно установить её командой:

```powershell
pyenv install 3.12.10
pyenv local 3.12.10
```

### Установка uv

Если `uv` ещё не установлен:

```powershell
pip install uv
```

Проверка установки:

```powershell
uv --version
```

### Создание виртуального окружения и установка зависимостей

Из корневой папки проекта выполните:

```powershell
uv sync --all-groups
```

Команда автоматически создаст виртуальное окружение `.venv`, разрешит зависимости, установит основные и dev-библиотеки и создаст или обновит `uv.lock`.

Для запуска Python и инструментов проекта рекомендуется использовать `uv run`:

```powershell
uv run python --version
uv run pytest
```

При необходимости окружение можно активировать вручную в PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

### Экспорт зависимостей

`pyproject.toml` является основным файлом описания зависимостей, а `uv.lock` фиксирует их точные версии.

При необходимости можно экспортировать зависимости в формат `requirements.txt`:

```powershell
uv export --format requirements.txt --no-dev --no-hashes --output-file requirements.txt
```

## 8. Воспроизводимость экспериментов

Для обеспечения воспроизводимости:

- фиксируются random seed;
- используется единый протокол разбиения данных;
- оптимизаторы получают одинаковый вычислительный бюджет;
- конфигурации экспериментов сохраняются;
- результаты отдельных запусков сохраняются до агрегации;
- точные версии зависимостей фиксируются в `uv.lock`.

Все итоговые графики и таблицы должны строиться на основе сохранённых результатов экспериментов, а не только на основе вывода исследовательских ноутбуков.
